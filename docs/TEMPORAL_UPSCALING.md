# Temporal upscaling: source baseline

Source inventory checked 2026-11-10. Paths are relative to `Witch-Time/`.
This is a source inspection, not an acceptance of a build or a device result.

- The inspected repository HEAD is `f4af93c`, following `35fbdd0` (memory ordering/coherency) and `374043c` (Android native-scale bootstrap). The memory/throughput change remains in progress; its checked source tasks and committed code do not establish device acceptance.

## Renderer and shim inventory

- `runtime/gfx_options.c`: `opt_load` initializes scale to 1.0 and upscaler off; `upscaler_of` parses legacy modes and `WT_UPSCALER` overrides the file. The explicit low profile has separate 0.5 scale behavior. `gfx_option_set` applies settings, including the upscaler, from a reread copy.
- `runtime/nvn_vk_draw.c`: `rs_scale` latches the option and derives scene scale using `fsr_ratio`, with the existing floor at 1.0 or selected output scale if lower. `rs_apply` recreates affected images. Do not lift that floor without qualifying complete game-grid stores and unsafe draw shapes.
- `draw_prepare` calls `fsr_draw` only when the draw is not potentially GPU-culled. `fsr_draw` captures qualifying depth and camera data, then calls `fsr_run` at the first qualifying bloom downsample or tonemap. `fsr_run` checks matching actual color/depth extents, initializes resources, records camera-motion and seven FSR passes, and routes output back to the scene. A recorded dispatch is not proof of GPU completion.
- `resolve_sampler` calls `fsr_dither_view` and `fsr_up_view`: the latter can supply the output to a promoted tonemap, but can also fill it with a linear fallback if FSR did not run. Dither-pattern discovery occurs before the running check and is not execution evidence. `fsr_present` advances the current FSR frame and disables jitter after a missed frame; `fsr_shutdown` releases its pipelines, layouts, samplers and uniform buffer.
- `runtime/game_shim_eh.c` `h_cam_upload` reads `game_fsr_w`, `game_fsr_h` and `game_fsr_phases`, temporarily jitters the selected camera upload, then restores the CPU-side matrices. `fsr_draw` copies camera constants into `F.c3`; guest-buffer reuse and correspondence across scenes still require dedicated tests.
- `rs_store_low`/`rs_store_done` are called from the direct and indexed draw paths and reuse a full-grid replay while excluding fragment stages that also write buffers. `resolve_image` and `rs_pyramid_next` are related storage/depth-size paths. Existing source and desktop notes do not qualify every indirect, conditional or mixed-side-effect path on Android.

## Producer and timing contracts

- `Slot.serial`, `R.serial` and `R.done` track ordered submissions and completed fences. `vt_garbage` defers image destruction by serial; future history resources must remain alive through their own GPU users. `CB.wserial` records the producing submission; storing draw and dispatch paths update it after preparation, and `indirect_src` can wait through that producer when `WT_VK_WRITERWAIT=1`. Preserve the host visibility barriers and conservative overlap fallback. `WT_VK_WRITERWAIT` and `WT_VK_LOADCLEAR` default off in this source.
- The provisional diagnostics transport has bounded producer records and separate GPU submit, completion and sample events (`runtime/diag.c`, `runtime/diag.h`). In `slot_wait`, a successful two-query result is converted using `timestampPeriod`; a failed or decreasing result is emitted as failed, not zero. The inspected production path does not account for the queue's timestamp valid bits or wrapped counters. `tests/diag_streaming_test.c` models wrap arithmetic separately and does not prove production handles it. Do not use this path as a qualified wrap-aware per-pass timing contract until corrected and reviewed in its owning change.
- GPU completion, summed submission durations, full-frame elapsed GPU spans, physical utilization and end-to-end frame delivery are distinct. Missing, pending, unsupported or failed observations cannot be interpreted as zero or as a performance win.

## Unchanged policy and outstanding qualification

This inventory changes no runtime defaults, graphics settings, query bypass, pacing, audio, saves or public guest interfaces. Matching module/build identities, accepted diagnostics source and its timing capabilities remain to be established; the independent implementation review and device-only tasks remain open. No shader algorithm repair or Find N5 quality, timing, deformation or 60 FPS claim follows from this note.

The current FSR capability gate also checks the 256-invocation X workgroup, eight workgroup rows, 4100 bytes of shared memory (the four 16×16 float SPD arrays and counter), nine storage images per stage and descriptor set, fifteen push descriptors, compute subgroup basic/QUAD support and sampling support for the allocated R16_SNORM LUT. It checks linear filtering for the internal image formats actually sampled with the linear sampler in the inspected shader permutation. `tests/fsr_limits_test.c` exercises limit boundaries using the production helper, and the shader reflection test checks the set of linearly sampled shader inputs; these are host-side checks, not Vulkan or device qualification. NDK r28c compiled the Android `nvn_vk.c` translation unit to an object after expanding its `#embed` directives in a temporary copy, with the existing Android dependency headers; one existing exhaustive-switch warning remained. This was not a link, game run or device test. Other required format, image-usage and resource-limit checks remain open.

The plan calls for LUT filtering checks. The current shader defines upsample Lanczos type 2 (approximate) and reproject type 0 (reference), while the linear LUT sampling function belongs to type 1. The host still creates and binds a LUT. An accumulate shader expanded like `fsr_emit` and compiled with NDK r28c `glslc` for Vulkan 1.3 retains the LUT descriptor but has no instruction loading it; this is not the runtime glslang output and does not qualify the device. Check the actual emitted runtime shader and LUT image requirements before requiring linear filtering or declaring that requirement unnecessary. No LUT filter rejection has been added on this evidence.

All seven vendored FSR compute passes also compiled with the same NDK shaderc permutation. Disassembly reports `StorageImageExtendedFormats` in each; the two pyramid passes report subgroup basic and quad, and accumulate reports `StorageImageWriteWithoutFormat`. Vulkan's SPIR-V capability table lists `StorageImageExtendedFormats` as core Vulkan 1.0; this does not by itself establish every image format's required support. These are compiler-side observations, not a runtime glslang or GPU result.

`tests/fsr_shader_test.py <glslc> <spirv-dis>` extracts the actual host permutation, expands embedded includes and compares the seven shaderc outputs against the host descriptor bindings/types and FSR/SPD constant offsets. It also checks camera-motion binding numbers and uniform offsets. It passed with NDK r28c's shader tools. `tests/fsr_cleanup_test.py` exercises the production release helper with mocked partial Vulkan setups and verifies both nonfatal compile and pipeline-creation failures invoke it. Vulkan calls covered by the existing fatal `VKC` path still terminate rather than return a recoverable error. No algorithm defect was established by these checks, so no FSR algorithm was changed. These results do not establish runtime-glslang equivalence, all camera descriptor types or GPU correctness; SPD device-scope behavior is unqualified and is not claimed as an observed failure.
