## Renderer and shim inventory

- `runtime/gfx_options.c`: `opt_load` initializes scale to 1.0 and upscaler off; `upscaler_of` parses legacy modes and `WT_UPSCALER` overrides the file. The explicit low profile has separate 0.5 scale behavior. `gfx_option_set` applies settings, including the upscaler, from a reread copy.
- `runtime/nvn_vk_draw.c`: `rs_scale` latches the option and derives scene scale using `fsr_ratio`, with the existing floor at 1.0 or selected output scale if lower. `rs_apply` recreates affected images. Do not lift that floor without qualifying complete game-grid stores and unsafe draw shapes.
- `draw_prepare` calls `upscale_draw` only when the draw is not potentially GPU-culled. `runtime/nvn_vk_upscale.c` captures matching scene color/depth identities and a copied camera snapshot, then dispatches the selected FS SGSR or FSR backend at the first qualifying bloom downsample or tonemap. Different cameras or jitter within one target generation invalidate the snapshot instead of mixing it. FSR retains its own algorithm/history; `fsr_run` checks matching actual color/depth extents, initializes resources, records camera-motion and seven FSR passes, and routes output back to the scene. A recorded dispatch is not proof of GPU completion.
- `resolve_sampler` calls `fsr_dither_view` and `fsr_up_view`: the latter can supply the output to a promoted tonemap, but can also fill it with a linear fallback if FSR did not run. Dither-pattern discovery occurs before the running check and is not execution evidence. `fsr_present` advances the current FSR frame and disables jitter after a missed frame; `fsr_shutdown` releases its pipelines, layouts, samplers and uniform buffer.
- `runtime/game_shim_eh.c` `h_cam_upload` reads `game_fsr_w`, `game_fsr_h` and `game_fsr_phases`, temporarily jitters the selected camera upload, then restores the CPU-side matrices. The shared scene snapshot copies camera constants before guest-buffer reuse. `tests/upscale_scene_test.c` and `tests/upscale_route_test.c` exercise identity, camera conflicts, skipped scenes, ordering and the production route with mocked renderer state. This is not device evidence; extra CPU work from camera comparison is unmeasured.
- `rs_store_low`/`rs_store_done` are called from the direct and indexed draw paths and reuse a full-grid replay while excluding fragment stages that also write buffers. `resolve_image` and `rs_pyramid_next` are related storage/depth-size paths. Existing source and desktop notes do not qualify every indirect, conditional or mixed-side-effect path on Android.
- `tests/rs_store_test.py` executes those production replay state transitions against mocked targets and queries, checks both direct/indexed call ordering and checks that indexed replay prepares the index range again. `tests/rs_store_coverage_test.c` shows that a CPU sentinel grid detects omitted rows/columns at odd reduced extents; its complete replay is a model, not Vulkan rendering. Neither check establishes GPU image coverage, synchronization or unsupported draw-shape safety; the temporal scale floor remains in place.
- `tests/rs_store_gpu_test.py <glslc>` now adds a real desktop GPU coverage model with the extracted production eligibility and replay helpers. Twelve direct/indexed, odd-extent, image-only/mixed-buffer cases pass; six deliberately skipped replay cases detect untouched rows and columns. Image-only cases prove complete GPU stores; mixed-buffer cases deliberately reject replay and check atomic counts for no duplicate buffer writes, not complete reduced-grid storage. Viewport/draw orchestration and target/query state are still modeled, and actual `exec`, replay ring wrapping, indirect/conditional/tessellation paths remain unqualified. Independent review accepted this narrow evidence, not tasks 3.2/3.4 or floor removal.
- `tests/upscale_scale_test.py` executes the production scale and size calculations with mocked options at native, sub-native and supersampled output scales, all existing FSR ratios, minimum/maximum limits and an odd extent. A quality request clamped by the existing floor now reports its requested and effective scales. This does not qualify lower temporal rendering or complete task 3.1.
