## Renderer and shim inventory

- `runtime/gfx_options.c`: `opt_load` initializes scale to 1.0 and upscaler off; `upscaler_of` parses legacy modes and `WT_UPSCALER` overrides the file. The explicit low profile has separate 0.5 scale behavior. `gfx_option_set` applies settings, including the upscaler, from a reread copy.
- `runtime/nvn_vk_draw.c`: `rs_scale` latches the option and derives scene scale using `fsr_ratio`, with the existing floor at 1.0 or selected output scale if lower. `rs_apply` recreates affected images. Do not lift that floor without qualifying complete game-grid stores and unsafe draw shapes.
- `draw_prepare` calls `upscale_draw` only when the draw is not potentially GPU-culled. `runtime/nvn_vk_upscale.c` captures matching scene color/depth identities and a copied camera snapshot, then calls `fsr_run` at the first qualifying bloom downsample or tonemap. Different cameras or jitter within one target generation invalidate the snapshot instead of mixing it. FSR retains its own algorithm/history; `fsr_run` checks matching actual color/depth extents, initializes resources, records camera-motion and seven FSR passes, and routes output back to the scene. A recorded dispatch is not proof of GPU completion.
- `resolve_sampler` calls `fsr_dither_view` and `fsr_up_view`: the latter can supply the output to a promoted tonemap, but can also fill it with a linear fallback if FSR did not run. Dither-pattern discovery occurs before the running check and is not execution evidence. `fsr_present` advances the current FSR frame and disables jitter after a missed frame; `fsr_shutdown` releases its pipelines, layouts, samplers and uniform buffer.
- `runtime/game_shim_eh.c` `h_cam_upload` reads `game_fsr_w`, `game_fsr_h` and `game_fsr_phases`, temporarily jitters the selected camera upload, then restores the CPU-side matrices. The shared scene snapshot copies camera constants before guest-buffer reuse. `tests/upscale_scene_test.c` and `tests/upscale_route_test.c` exercise identity, camera conflicts, skipped scenes, ordering and the production route with mocked renderer state. This is not device evidence; extra CPU work from camera comparison is unmeasured.
- `rs_store_low`/`rs_store_done` are called from the direct and indexed draw paths and reuse a full-grid replay while excluding fragment stages that also write buffers. `resolve_image` and `rs_pyramid_next` are related storage/depth-size paths. Existing source and desktop notes do not qualify every indirect, conditional or mixed-side-effect path on Android.
- `tests/rs_store_test.py` executes those production replay state transitions against mocked targets and queries, checks both direct/indexed call ordering and checks that indexed replay prepares the index range again. `tests/rs_store_coverage_test.c` shows that a CPU sentinel grid detects omitted rows/columns at odd reduced extents; its complete replay is a model, not Vulkan rendering. Neither check establishes GPU image coverage, synchronization or unsupported draw-shape safety; the temporal scale floor remains in place.
- `tests/upscale_scale_test.py` executes the production scale and size calculations with mocked options at native, sub-native and supersampled output scales, all existing FSR ratios, minimum/maximum limits and an odd extent. A quality request clamped by the existing floor now reports its requested and effective scales. This does not qualify lower temporal rendering or complete task 3.1.

## FSR execution observations

The `nvn_vk_fsr: evidence` line records the post-override requested option and the mode latched by `rs_scale`, capability gate result, initialized state, whether an eligible scene was found, whether dispatch commands were recorded, whether the tonemap's sampled view was bound, whether a non-empty direct/CPU-resolved draw was recorded with that view, and whether the up-view fallback was used. Logging is limited to 32 state/mode transitions; it is not a continuous counter. A dither pattern discovery does not change these observations. `consumer_recorded` means a command was recorded, not GPU completion, visible pixels, image quality or performance. GPU-count/indirect draws that cannot be proven nonempty do not claim consumption. An input-extent mismatch, a missing consumer and a setup failure remain distinct outcomes.

For an approved single-run investigation, retain the complete bounded log with binary/build identity and effective settings, then check the same run for a matching scene, FSR initialization, recorded dispatch, and a recorded tonemap consumer. Capture errors and fallback lines as well as successes. Do not equate this recipe with a device acceptance run or infer success from a setting or dither line; actual GPU completion and visual correctness need their own evidence.

The same cross-compile/no-OpenGL-import check also passed at API 29, the current `android/app/build.gradle` minimum; its trap test remained skipped. The earlier API 28 failure is below that declared minimum and is not evidence of an API 29 build failure.

With Windows GCC (`-std=c11 -O2 -Wall -Wextra -Werror -Iruntime`), the following host checks also passed: `rs_pyramid_test`, `fsr_dither_test`, `fsr_limits_test`, `fsr_evidence_test`, `upscale_scene_test`, `upscale_route_test`, `sgsr_params_test` and `rs_store_coverage_test`. The last is a CPU sentinel model and the route test uses mocked renderer state. Task 9.1 remains open until the remaining integration and Android-link checks are complete.

All pinned upstream fragment and compute shader sources are present under `runtime/third_party/sgsr2/`. The shaderc test verifies their upstream blob identities and compiles all five compute stages: both 2-pass stages retain colliding descriptor bindings and must be remapped before Vulkan integration; the three 3-pass stages have unique binding numbers in the inspected output. The fragment backend is now implemented in `runtime/nvn_vk_sgsr.c`; compute integration and runtime Android glslang qualification remain open.

The FS preparation uses the existing NDK `glslc` (shaderc v2022.3, glslang ndk-r27-beta1) with Vulkan 1.3 and `REQUEST_NDC_Y_UP=1`; `tests/sgsr_shader_test.py` checks the vertex varying, fragment descriptors and uniform member offsets, and `tests/sgsr_params_test.c` asserts the 128-byte host structure. The unchanged upstream sample vertex expects a mesh and lacks a Vulkan output location; `sgsr2_vertex.h` instead supplies the existing renderer-style fullscreen triangle with location 0. This offline compiler is not the runtime's Android glslang binary, and these chosen layouts have not yet been used by a production SGSR pipeline.

The fragment backend emits Vulkan GLSL 450, bounds integer texture fetches, promotes mediump declarations to highp for HDR variance, and removes raster jitter before applying the unjittered camera reprojection. `tests/sgsr_source_test.py` compiles the actual production source adapter and checks descriptors, emitted clamps, highp and a nonidentity analytic jitter case. The upstream files remain byte-pinned and unchanged.

For the compute variants, the same reflection test now checks every upstream uniform member offset against the asserted 144-byte `Sgsr2CsParams` layout. It also compiles a temporary 2-pass binding-remap experiment using storage bindings 10 and 11, checking descriptor types and uniqueness. This experiment does not alter the pinned sources, and no production compute backend uses the remap yet; bounds, HDR and GPU behavior remain unverified.

The parser and settings row reserve `sgsr2`, `sgsr2_quality` and `sgsr2_performance` as modes 6–8 without changing legacy modes 0–5. `WT_SGSR_VARIANT` accepts `2-pass-fs` (default), `2-pass-cs` or `3-pass-cs`; an unknown value is invalid. Only fragment SGSR executes so far, at the selected native scene scale; reduced-scene quality ratios remain limited pending store qualification. Compute variants and invalid selectors explicitly fall back to native rather than entering FSR. `tests/upscaler_config_test.py` covers the production parsers and source-level override ordering. The menu self-test passed on Windows using a temporary expanded-embed copy, adaptations for Windows `mkdir`/environment calls and an LF-normalized temporary copy of the shipped INI; it checked environment precedence, legacy files and apply-on-close without changing the user's settings. This is not Android validation.

Fragment resources are sampled/attachment/transfer RGBA16F motion and two output histories plus a render-size sampled/transfer zero-velocity image. No storage-image support is imposed on FS. Constants live in the existing GPU-safe stream ring, now also declared for uniform-buffer use. Resize creates a complete new generation before retiring old images; failed unreferenced partial generations are destroyed. Backend setup reports the failing pass and Vulkan/compiler operation and releases partial pipeline/layout/sampler state. Allocation exhaustion inside the existing `vmem_alloc` retains the renderer's fatal policy, not a promised recoverable fallback. Each custom pass invalidates graphics state shadows before subsequent game draws.

Host verification: `tests/sgsr_cleanup_test.py` executes production cleanup for all 256 partial handle combinations; `tests/sgsr_resources_test.py` executes production resize/retirement with injected allocation failures, checks render-sized zero fallback and native identity swizzles, and checks state invalidation and attachment-vs-storage roles. Android API29 `nvn_vk.c` compiles to an object with the new unit after temporary embed expansion (existing switch warning only). This is not a strict runtime link or device run.

`python tests/sgsr_gpu_test.py <glslc> <spirv-dis>` passed twelve headless RTX 5070 Ti ping-pong/readback cases: 17×13 native, 17×13→25×19, 1×1, black, HDR1000 and HDR60000, each with reset and seeded constant history. Each case executes Convert and two Upscale passes with separately bound alternating outputs; every RGB output was finite and within max(0.02, 0.2%) of the constant input, including borders. These exercise production-emitted fragment shaders with a separate minimal Vulkan harness, not production allocation/pipeline orchestration. Tasks 4.3/4.4 remain open.

Four added raw-HDR intensity transitions use current/history pairs 1000/4, 4/1000, 60000/0 and 0/60000 with reset disabled and alternating outputs. The shared scene is invalidated when the latched mode changes, even if scale does not. Existing FSR images are queued through `vt_garbage` and its submission serial instead of being destroyed immediately; camera/history continuity and jitter exports are reset. A changed swapchain/surface generation also resets FSR history. Progress and held presentations are wired not to advance the FSR frame. `tests/upscale_route_test.c` and `tests/upscale_lifecycle_wiring_test.py` cover mocked retirement and source-level boundaries, not an in-flight GPU execution. SGSR history and full mode-switch/device lifecycle qualification are still pending task 2.3.

The scene's `ran` and fallback-output frame markers start at -1 rather than zero, so an eligible first scene at frame zero is not incorrectly treated as already processed. The scene and production-route host tests exercise that first-frame case; they do not show that the game reaches such a scene or that the GPU executes it.

## Producer and timing contracts

- `Slot.serial`, `R.serial` and `R.done` track ordered submissions and completed fences. `vt_garbage` defers image destruction by serial; future history resources must remain alive through their own GPU users. `CB.wserial` records the producing submission; storing draw and dispatch paths update it after preparation, and `indirect_src` can wait through that producer when `WT_VK_WRITERWAIT=1`. Preserve the host visibility barriers and conservative overlap fallback. `WT_VK_WRITERWAIT` and `WT_VK_LOADCLEAR` default off in this source.
- The provisional diagnostics transport has bounded producer records and separate GPU submit, completion and sample events (`runtime/diag.c`, `runtime/diag.h`). In `slot_wait`, a successful two-query result is converted using `timestampPeriod`; a failed or decreasing result is emitted as failed, not zero. The inspected production path does not account for the queue's timestamp valid bits or wrapped counters. `tests/diag_streaming_test.c` models wrap arithmetic separately and does not prove production handles it. Do not use this path as a qualified wrap-aware per-pass timing contract until corrected and reviewed in its owning change.
- GPU completion, summed submission durations, full-frame elapsed GPU spans, physical utilization and end-to-end frame delivery are distinct. Missing, pending, unsupported or failed observations cannot be interpreted as zero or as a performance win.

## Unchanged policy and outstanding qualification

This inventory changes no runtime defaults, graphics settings, query bypass, pacing, audio, saves or public guest interfaces. Matching module/build identities, accepted diagnostics source and its timing capabilities remain to be established; the independent implementation review and device-only tasks remain open. No shader algorithm repair or Find N5 quality, timing, deformation or 60 FPS claim follows from this note.

The current FSR capability gate checks the 256-invocation X workgroup, eight workgroup rows, dispatch-grid limits, 4100 bytes of shared memory (the four 16×16 float SPD arrays and counter), per-stage and per-set descriptor limits, fifteen push descriptors, compute subgroup basic/QUAD support and sampling support for the allocated R16_SNORM LUT. It checks linear filtering for the internal image formats actually sampled with the linear sampler in the inspected shader permutation. It also queries the sampled/storage/transfer image-usage combinations and the actual resize extents, mip counts and single-sample support before allocation. `tests/fsr_limits_test.c` and `tests/fsr_image_usage_test.py` exercise the production decisions with mocked properties, and the shader reflection test checks the filtered resources and their bound formats. These are host-side checks, not Vulkan or device qualification. NDK r28c compiled the Android `nvn_vk.c` translation unit to an object after expanding its `#embed` directives in a temporary copy, with the existing Android dependency headers; one existing exhaustive-switch warning remained. This was not a link, game run or device test.

Formatless output writes are accepted when either the global feature is enabled or Vulkan 1.3 reports the format-specific write-without-format bit, provided the sampled/storage/transfer image usage is supported. If the scene format cannot be used as output, RGBA16F is used only when supported; unsupported output-to-scene blits disable FSR and restore the baseline scale. The helper's global/per-format cases have host-only tests; actual device behavior still needs qualification.

A disposable Windows host probe using the production image-query functions and the Vulkan loader reported both RGBA16F and B10G11R11 output usages supported on an RTX 5070 Ti (NVIDIA driver 621.01; global formatless-write feature present). This was a property query only: no rendering, synchronization validation or Android/Adreno conclusion follows from it. The loader also reported a missing Epic overlay manifest; the probe still completed.

The plan calls for LUT filtering checks. The current shader defines upsample Lanczos type 2 (approximate) and reproject type 0 (reference), while the linear LUT sampling function belongs to type 1. The host still creates and binds a LUT. An accumulate shader expanded like `fsr_emit` and compiled with NDK r28c `glslc` for Vulkan 1.3 retains the LUT descriptor but has no instruction loading it; this is not the runtime glslang output and does not qualify the device. Check the actual emitted runtime shader and LUT image requirements before requiring linear filtering or declaring that requirement unnecessary. No LUT filter rejection has been added on this evidence.

All seven vendored FSR compute passes also compiled with the same NDK shaderc permutation. Disassembly reports `StorageImageExtendedFormats` in each; the two pyramid passes report subgroup basic and quad, and accumulate reports `StorageImageWriteWithoutFormat`. Vulkan's SPIR-V capability table lists `StorageImageExtendedFormats` as core Vulkan 1.0; this does not by itself establish every image format's required support. These are compiler-side observations, not a runtime glslang or GPU result.

`tests/fsr_shader_test.py <glslc> <spirv-dis>` extracts the actual host permutation, expands embedded includes and compares the seven shaderc outputs against the host descriptor bindings/types and FSR/SPD constant offsets. It also checks camera-motion descriptor bindings/types and uniform offsets. It passed with NDK r28c's shader tools. `tests/fsr_cleanup_test.py` exercises the production release helper with mocked partial Vulkan setups and checks cleanup on the sampler, descriptor-layout, pipeline-layout, compile and pipeline-creation failure branches. Other Vulkan calls covered by the existing fatal `VKC` path still terminate rather than return a recoverable error. No algorithm defect was established by these checks, so no FSR algorithm was changed. These results do not establish runtime-glslang equivalence or GPU correctness; SPD device-scope behavior is unqualified and is not claimed as an observed failure.
